# FinGuard AI: Outbound Response Enforcement Capabilities & Limitations

**Document Version**: 1.0.0  
**Domain**: Egress Safety, Ground-Truth Verification, and Provider-Independent Response Interception  

---

## 1. Provider Independence Architecture

FinGuard AI's outbound response enforcer operates **100% independently from the LLM provider** (OpenAI, Anthropic, Ollama, vLLM, local open-source models). The enforcer intercepts raw completion strings in-flight before payload transmission to client applications.

```
[ LLM Provider Completion ] ----> [ Outbound Response Enforcer ] ----> [ Client App ]
                                          |
                      +-------------------+-------------------+
                      |                   |                   |
               [ Secret Leak Scan ] [ Unsafe Claims ] [ Ground-Truth Verifier ]
```

---

## 2. Ground-Truth Rate Verification Boundaries

> [!IMPORTANT]
> **VERIFICATION BOUNDARIES & LIMITATIONS**
> 1. **Structured Supported Fields**: Fact verification is performed deterministically for **explicitly supported structured fields** (e.g. product interest rates, minimum balances, maximum loan tenures, and approved FAQ strings).
> 2. **No Free-Text Verification Claim**: String matching and pattern extraction **cannot verify every open-ended natural language claim** generated by an LLM.
> 3. **Automatic Fallback on Discrepancy**: If an LLM completion generates a rate claim that contradicts approved ground-truth data (e.g. claims *Fixed Deposit rate is 7.5%* when approved ground truth is *6.5%*), the gateway automatically corrects the text or returns a safe fallback notice (`FALLBACK_SAFE_RESPONSE`).

## 4. Outbound Safety Rules & Precedence

1. **Secret & Key Leak Block**: If an output completion contains raw AWS secret keys (`AKIA...`), database credentials, or RSA private key strings, the gateway triggers `BLOCK` with `OUTBOUND_SECRET_KEY_LEAK_BLOCKED` and returns `SAFE_FALLBACK_RESPONSE`.
2. **Unsafe Claim Block**: Prompts containing claims of "guaranteed 100% profit" or "zero risk stock" trigger `BLOCK` with `OUTBOUND_UNSAFE_FINANCIAL_CLAIM_BLOCKED`.
3. **Stale Ground-Truth Version**: If the requested ground-truth data version is stale or missing, the gateway triggers `ESCALATE` with `OUTBOUND_STALE_GROUND_TRUTH_VERSION_ESCALATED`.
4. **Mandatory Disclaimer Injection**: Responses offering general investment guidance automatically have statutory disclaimers appended (`OUTBOUND_DISCLAIMER_APPENDED`).
